# Minecraft Bedrock 空間幾何・物理仕様ノート

アドオン開発および物理シミュレーションの実装・検証を通じて判明した、**マインクラフト統合版（Bedrock Script API `@minecraft/server`）における普遍的な空間幾何・物理演算・API挙動の仕様まとめ**です。

---

## 1. ブロックレイキャスト（`BlockRaycastHit`）の座標系と既知の不具合

### ① `hit.faceLocation` はローカル相対座標（$0.0 \sim 1.0$）
- `dimension.getBlockFromRay()` で得られる `hit.faceLocation` は、ワールド座標ではなく**衝突したブロックの北西下隅（`block.location`）を原点 $(0, 0, 0)$ としたブロック内相対座標**です。
- プレイヤーのワールド座標（`player.location`）と直接差分を取ると、プレイヤーのワールド座標値そのものが誤差として混入します。

### ② MCPE-223452 バグによる「1m過剰見積もり」現象
- Mojang の既知の不具合（**MCPE-223452**）により、ワールドの座標や面の向きによって `hit.faceLocation` が本来 $0.0$ のはずの面で $1.0$ になるなど、**1ブロック分（1.0m）奥にズレた座標を返す**現象が存在します。
- そのため、`block.location + hit.faceLocation` で復元したワールド座標も 1m 奥にズレてしまいます。

### ③ 普遍的な回避策: 面（`hit.face`）から平面座標を直接幾何計算
`hit.faceLocation` に依存せず、衝突ブロックの整数座標 `hit.block.location` と衝突面 `hit.face`（`Direction`）から、**面のワールド平面座標を直接決定**するのが最も安全かつ厳密です。

- **北面（Direction.North）**: $Z = block.location.z$
- **南面（Direction.South）**: $Z = block.location.z + 1.0$
- **西面（Direction.West）**: $X = block.location.x$
- **東面（Direction.East）**: $X = block.location.x + 1.0$

進行方向単位ベクトル $\vec{dir}$ とレイ始点 $\vec{pos}$ に対する進行方向の交差距離 $t$:
$$t = \frac{\text{平面座標} - pos_{\text{axis}}}{dir_{\text{axis}}}$$

## 2. 密着・境界接触時におけるレイキャストのトンネリング（すり抜け）

### ① 境界上のレイキャスト不発挙動
- レイの始点がブロックの表面（境界面）または微小な浮動小数点誤差でブロック内部に入り込んでいる場合、`getBlockFromRay` はそのブロックを衝突対象として認識できず、**手前のブロックをすり抜けて背後のブロックを検知するか、`undefined` を返す**挙動を示します。

### ② 普遍的な解決策: わずかな後退オフセット（Back-Offset）
- 密着しているブロックの表面を確実に捉えるには、レイの始点を進行方向と逆向きに微小量（例: `0.05m`）後退させた位置から照射します。
  $$\vec{startPos} = \vec{pos} - \vec{dir} \times 0.05$$
- 計算された交差距離 $t$ を $\max(0, t)$ でクランプすることで、密着時は即座に距離 $0.0\text{m}$ として安全に判定できます。

## 3. スプリントジャンプの初速ボーナス（バニラ物理）

- マインクラフトでは、スプリント（ダッシュ）状態でジャンプを行うと、**水平進行方向（XZ平面）に約 `+0.2 blocks/tick` の追加初速（ボーナスインパルス）**が付与されます。
- この水平加速は垂直初速度（約 $0.42 \sim 0.46\text{ blocks/tick}$）と同時に付与され、長距離跳躍や段差越えの基本物理特性を形成しています。

---

## 4. 段差乗り越えにおける放物線軌道の同期原則

- 移動しながら段差を乗り越える際、障害物の壁面に激突してから跳び上がると、水平速度が急減速してしまいます。
- 減速せずにスムーズに上面へ乗り上げるためには、**障害物到達までの時間（$t_{\text{reach}}$）** と **目標高度までの最高点到達時間（$t_{\text{apex}}$）** を同期させ、
  $$t_{\text{reach}} = \frac{\text{distance}}{\text{horizontalSpeed}} < t_{\text{apex}}$$
  となった直前のタイミングでジャンプを開始する必要があります。これにより、ブロックの端を通過する瞬間に足元が上面を超える放物線軌道が成立します。

## 5. 接地判定（`isOnGround`）の同期遅延とブロック角の疑似接地（Edge Glitch）

### ① クライアント同期遅延による多重インパルス現象
- Bedrock Edition ではプレイヤーの移動・接地判定がクライアント主導（Client-Authoritative）で処理されています。
- スクリプトから `applyImpulse` を実行した直後、クライアント側で離陸（`!isOnGround`）した結果がサーバーに反映されるまでに数 tick のパケット往復遅延が生じます。
- 固定 Tick 数のクールダウンだけに依存すると、ラグ発生時に「まだ接地している」と判定されてジャンプインパルスが二重加算（多重発動）される原因となります。
- **普遍的対策**: 一度ジャンプを実行したら「空中に離陸した（`!isOnGround`）後に、再び着地する（`isOnGround`）」まで再発動を遮断する離陸・着地ステートマシンが有効です。

### ② ブロック角（コーナー）通過時の疑似接地と $v_y > 0$ ガード
- 空中ジャンプ中であっても、隣接ブロックの角や段差の縁を斜めにかすめた瞬間に、物理エンジンが一瞬 `isOnGround = true` を返す「疑似接地（Edge Glitch）」が発生することがあります。
- 平坦な地面に立っている・歩行している間は $v_y = 0.0$ であり、$v_y > 0$（上昇中・跳躍中）である場合は確実に空中にいる状態であるため、$v_y > 0$ のときはジャンプ発動を遮断することでコーナーでの暴発を完全に防げます。

### ③ 離陸未検知（壁押し・頭上遮蔽）によるステート永久ロックとタイムアウト救済
- 離陸・着地ステートマシンにおいて、壁面に押し当てられた状態や頭上にブロックがある状態でインパルスを与えた場合、クライアント側の垂直移動が即座に衝突解消され、サーバー側で一度も `!isOnGround`（空中判定）が受信されないケースが存在します。
- この場合、着地解除条件が満たされず「離陸待ち」のままステートが永久にロックされ、以後のアクションが一切発動しなくなる恐れがあります。
- **普遍的対策**: クールダウン完了から数 tick（例: 5〜10 tick）経過しても離陸が検知されない場合は、強制的に待機ステートを解除するタイムアウト復帰（フェイルセーフ）を必ず設けます。

## 6. 段差登坂限界（Step Height = 0.6m）と特殊ブロックの当たり判定特性

### ① プレイヤーの歩行登坂限界（0.6m）とレイ照射高さ
- マインクラフトのプレイヤーは、高さ **0.6m 以下の段差**（ハーフブロック: 0.5m、ベッド: 0.5625m 等）であれば、ジャンプせず通常の歩行だけで自動ステップアップして乗り越えられます。
- 段差検知レイキャストの照射高さを足元から **`0.61m` 以上（0.6m より上）** に設定することで、歩行で登れる段差の上空をレイが通過し、不要なオートジャンプの誤発動を幾何学的に完全に除外できます。

### ② 階段とフェンスの物理特性
- **階段ブロック**:
  - バニラでは歩行登坂可能な傾斜面として処理されるため、ジャンプ判定の対象外とするのが望ましい。
- **フェンスブロック**:
  - 見た目は 1 ブロック（1.0m）ですが、当たり判定（コリジョンボックス）の高さは **1.5m** 存在します。
  - 通常のバニラジャンプ（最高到達高度 約 1.25m）や、1.0m 級のジャンプ（1.5m 未満）では飛び越えられず激突するため、ジャンプ目標高度が 1.5m 未満である場合は除外対象とする必要があります。
